## Overview

The **BinRack Wise Stock Movement Report&#x20;**&#x67;ives a complete view of stock movements at the batch and bin level in the warehouse management system (WMS).

It tracks all inbound, outbound, return, adjustment, and transfer transactions, while providing running balance calculations per batch, warehouse, and bin.

<Callout kind="tip" collapsed="false">
  Balance Quantity = Running total of Qty per Item / Batch / Warehouse / Bin
</Callout>

---

## Purpose

This report:

- Tracks batch-level stock movements

- Classifies movements into Transaction Types: Inward, Outward, Return, Adjustment, Transfer

- Provides detailed bin-level inventory tracking

- Includes running balance calculations

- Supports filtering by warehouse, item, and category

👉 In short:\
Understand exactly how stock moves across batches and bins over time.

## How It Works

<Steps>
  <Step title="Step 1: Define Date Range" icon="calendar" title-type="p">
    Converts input dates into a datetime range:

    - Start → @DateFrom

    - End → @DateTo + 1 day minus 1 millisecond for inclusivity
  </Step>

  <Step title="Step 2: Extract Batch Audit Data" icon="database" title-type="p">
    Pulls batch audit records from `batch_audit` table:

    - Includes quantity and value changes

    - Resolves source and destination bins using `warehouse_binrack`

    - Filters out zero-quantity movements
  </Step>

  <Step title="Step 3: Identify Transfer Jobs" icon="git-branch" title-type="p">
    Flags jobs where:

    - `fkJobId` is present

    - Sum of QuantityDelta = 0 (internal transfer)

    - Movement occurs across 2 or more bins

    - Used to classify movements as Transfer
  </Step>

  <Step title="Step 4: Classify Transaction Types" icon="tag" title-type="p">
    Determines movement type for each record:

    - Transfer → flagged from transfer\_jobs

    - Adjustment → ChangeNote contains 'Adjustment'

    - Return → Order ID exists and QuantityDelta > 0

    - Inward → QuantityDelta > 0

    - Outward → all others
  </Step>

  <Step title="Step 5: Join Batch and Item Data" icon="link" title-type="p">
    Adds metadata:

    - SKU, Item Title, Barcode

    - Category Name

    - Warehouse

    - Bin Rack

    - Reference number (Order / Job / Batch)
  </Step>

  <Step title="Step 6: Calculate Running Balance" icon="plus-circle" title-type="p">
    Computes running balance per:

    - SKU

    - Batch

    - Warehouse

    - Bin Rack\
      Uses `SUM() OVER (PARTITION BY ... ORDER BY ChangeDate, fkBatchInventoryId)`
  </Step>

  <Step title="Step 7: Apply Filters" icon="filter" title-type="p">
    Filters final results using parameters:

    - Warehouse = selected warehouse or ALL

    - ItemSearch = SKU or Title pattern

    - Category = selected category or ALL
  </Step>

  <Step title="Step 8: Sort Output" icon="arrow-down" title-type="p">
    Orders results by:

    - Transaction Date descending

    - Item Code ascending
  </Step>
</Steps>

## Important Notes

<Callout kind="warning" collapsed="false">
  - Only non-zero quantity movements are included

  - Transfer jobs are identified and flagged separately

  - Running balance is cumulative per SKU / Batch / Bin / Warehouse

  - Barcode is included for client reporting format

  - User attribution replaces RMA returns with 'RMA Process'

  - Filtering parameters are optional, use 'ALL' or empty string for full inclusion
</Callout>

## 1. Service Overview

The AI-Image-Enhancer is the final stage of the pipeline. It receives:

- A garment image URL (already background-removed or raw)

- An S3 path pointing to a `.txt` prompt file or a `.json` enhance profile

- Target output dimensions

- Various model hyperparameters

It then:

1. Optionally calls an external background-removal API (hardcoded IP)

2. Fetches the prompt or enhance profile from S3

3. Submits the image + prompt to fal.ai (a diffusion model hosting platform)

4. Polls for the result

5. Optionally applies LAB colour correction to preserve the original garment colours

6. Resizes the result to the target dimensions

7. Uploads the final image to S3

8. Returns the public S3 URL

The service runs on port 9090, exposes 6 image enhancement endpoints (one per AI model), plus management and health endpoints.

## 4. Startup and Entry Points

**Entry file:** `AI-Image-Enhancer/app.py`

```bash
uvicorn app:app --port 9090
```

(Port derived from Postman collection; `requirements.txt` does not specify startup command)

At module load (`app.py`):

1. `load_dotenv()` — reads `.env` file

2. Validates `FAL_KEY` env var — raises `ValueError` and aborts startup if missing

3. `IS_BACKGROUND_REMOVAL = True` — hardcoded global flag

4. `prompt_cache = {}` — in-memory dict initialized empty

5. AWS S3 client constructed:

   - If `SERVER == "true"`: `boto3.client("s3", aws_access_key_id=..., aws_secret_access_key=...)`

   - Else: `boto3.Session(profile_name="rishvi").client("s3", ...)` — named profile `"rishvi"`

6. FastAPI app instantiated

7. All 10 route handlers registered

**Critical startup requirement:** `FAL_KEY` must be set — the only hard startup guard in this service.

### Background Removal URL Rewrite — Critical Detail

This is done in the endpoint handlers **before** calling the pipeline:

```python
request.url = request.url.replace("files", "EditedFiles").rsplit('.', 1)[0] + ".jpeg"
```

**What this does:**

1. Replaces `"files"` with `"EditedFiles"` in the URL string

2. Strips the file extension

3. Appends `.jpeg`

**Example:**

- Input: `https://test-rishvi.s3.eu-west-2.amazonaws.com/files/product123.png`

- After rewrite: `https://test-rishvi.s3.eu-west-2.amazonaws.com/EditedFiles/product123.jpeg`

**Why:** The background removal API (external service at `77.68.113.204:4000`) Takes the image, removes the background, and stores the result at the `EditedFiles/` path in the same bucket. The URL rewrite tells the enhancement pipeline to pick up the background-removed version.

**Risk:** This string replacement is fragile. If `"files"` appears anywhere else in the URL (e.g., as part of a domain name, query string, or folder structure), it will be replaced incorrectly. Example: `"https://files.example.com/..."` → `"https://EditedFiles.example.com/..."`.

## 10. Business Logic Flow

### Standard Enhancement Flow (e.g., flux-kontext-pro)

```
Client POST /image-enhance/v1/flux-kontext-pro
│
├── FastAPI parses ImageEnhanceRequest via Pydantic
│
├── [if IS_BACKGROUND_REMOVAL == True]
│   ├── call_background_removal_api(url, bucketName, width, height, "jpeg")
│   │   └── requests.post("http://77.68.113.204:4000/api/image/upload-url-v4", 
│   │                      json={url, bucketName, width, height, extension})
│   │   └── Raises HTTP 500 on non-200 or request failure
│   └── request.url = url.replace("files", "EditedFiles").rsplit('.')[0] + ".jpeg"
│
└── process_image_enhancement(request, model_name="fal-ai/flux-pro/kontext")
    │
    ├── [if request.prompt.endswith(".json")]
    │   ├── get_enhance_profile(bucketName, prompt_s3_key)
    │   │   └── s3_client.get_object → json.loads()
    │   ├── prompt = profile["prompt"]
    │   └── request.guidance_scale = profile.get("guidance_scale", request.guidance_scale)
    │
    ├── [else: .txt prompt]
    │   └── get_prompt_from_s3_or_cache(bucketName, prompt_s3_key)
    │       ├── Check prompt_cache["{bucket}/{key}"]
    │       ├── On miss: s3_client.get_object → read text
    │       └── Store in prompt_cache
    │
    ├── process_image_with_fal(prompt, image_url, request, model_name)
    │   ├── Build arguments dict:
    │   │   {prompt, guidance_scale, num_images=1, output_format="jpeg", sync_mode=False}
    │   ├── Model-specific additions:
    │   │   ├── GEMINE_FLASH / NANO_BANANA / FLUX_2: image_urls=[url]
    │   │   ├── Others: image_url=url (singular)
    │   │   └── FLUX_2: image_size={width:884, height:1128}
    │   ├── Add safety_tolerance if set
    │   ├── Add aspect_ratio if set
    │   ├── await fal_client.submit_async(model_name, arguments=arguments)
    │   ├── result = await handler.get()
    │   ├── Extract result["images"][0]["url"]
    │   └── decode_image_from_url_or_data_uri(result_image_url) → bytes
    │
    ├── [if request.colour_match == True]
    │   ├── decode_image_from_url_or_data_uri(request.url) → original_bytes
    │   ├── colour_match_bytes(original_bytes, processed_image_data) → corrected_bytes
    │   └── On failure: log warning, use uncorrected bytes
    │
    └── upload_image_data_to_s3(image_data, bucketName, filePath, width, height)
        ├── PIL open → resize LANCZOS → save JPEG quality 95 → BytesIO
        ├── s3_client.upload_fileobj(..., ExtraArgs={ContentType: "image/jpeg", Metadata: {...}})
        ├── s3_client.head_object (verify upload succeeded)
        └── Returns: "https://{bucket}.s3.{region}.amazonaws.com/{key}"
```

## 11. AI/Image Processing Logic

### fal.ai Integration

fal.ai is a serverless GPU platform that hosts diffusion models via REST API. The Python `fal_client` SDK wraps the API.

**Authentication:** `FAL_KEY` environment variable — the `fal_client` SDK reads this automatically.

**Async submission pattern:**

```python
handler = await fal_client.submit_async(model_name, arguments=arguments)
result = await handler.get()   # Blocks until model completes
```

This is "async" in the Python sense (doesn't block the event loop while waiting), but the HTTP request still blocks until `handler.get()` returns. If fal.ai is slow, the client's request will appear to hang.

**`sync_mode=False`****:** Tells fal.ai to process asynchronously on their side (queue it, don't block their response). The `handler.get()` call then polls or subscribes to get the result.

### Model Differences (confirmed by code)

| Model                        | `image_url` param style   | `image_size` param                   | LoRA support        |
| ---------------------------- | ------------------------- | ------------------------------------ | ------------------- |
| `flux-pro/kontext`           | Single: `image_url="..."` | Not sent                             | No                  |

---

### LAB Colour Matching (`colour_match_bytes`)

**When used:** Only when `colour_match=True` in the request. Off by default.

**Why needed:** Diffusion models like FLUX can shift the colour of the output image, sometimes significantly. If the enhancement prompt says "preserve original colour" but the model still shifts the white balance or saturation, the `colour_match` step corrects it by transferring the original image's colour statistics onto the enhanced output.

**Algorithm:** Reinhard colour transfer in LAB colour space (see Section 16 for full algorithm deep dive).

---

### Image Resize (`upload_image_data_to_s3`)

```python
if target_width and target_height:
    img = Image.open(BytesIO(image_data))
    img = img.resize((target_width, target_height), Image.Resampling.LANCZOS)
    buffer = BytesIO()
    img.save(buffer, format="JPEG", quality=95)
    image_data = buffer.getvalue()
```

**LANCZOS resampling:** High quality downscaling filter — preserves detail better than bilinear. Correct choice for product photography where fine texture must be preserved.

**JPEG quality 95:** Near-lossless quality. Appropriate for product images that will be displayed on e-commerce sites.

**Note:** The resize always converts to JPEG regardless of input format. This means PNG images (if any) lose transparency at this stage.

## 12. Database/Storage/Queue Usage

### S3 (AWS Simple Storage Service)

**Bucket:** `request.bucketName` — caller-provided per request

**Reads:**

- `s3_client.get_object(Bucket=bucketName, Key=prompt_s3_key)` — fetch prompt or enhance profile

- The `"public/"` prefix is stripped from the `prompt` field: `s3_key = request.prompt.lstrip("/")` \[Confirmed by usage pattern — the `prompt` field contains the raw S3 key]

**Writes:**

- `s3_client.upload_fileobj(BytesIO(image_data), bucket, key, ExtraArgs={ContentType: "image/jpeg", Metadata: {processed-date, source, dimensions}})`

**Verification after write:**

- `s3_client.head_object(Bucket=bucket, Key=key)` — confirms the upload exists before returning success

**Region:** `eu-west-2` (hardcoded constant `AWS_REGION`)

**Auth:**

- `SERVER=true` → explicit `aws_access_key_id` + `aws_secret_access_key` env vars

- `SERVER=false` → `boto3.Session(profile_name="rishvi")` named profile

**`BACKGROUND_TEMP_BUCKET = "test-rishvi"`****&#x20;hardcoded** — used for background removal staging.

---

### `prompt_cache` (In-Memory)

```python
prompt_cache: dict = {}    # Module-level, lives for the lifetime of the process
```

**Key:** `"{bucket}/{s3_key}"` — e.g. `"test-rishvi/prompts/job-abc123-front.txt"`

**Value:** The prompt string (or extracted `"prompt"` field from JSON profile)

**Cache behavior:**

- **Hit:** Returns cached string immediately, no S3 call

- **Miss:** Fetches from S3, caches result, returns string

- **Eviction:** None — the cache grows indefinitely. There is no TTL, no size limit, no LRU eviction.

- **Invalidation:** Manual via `DELETE /cache/prompts` endpoint (clears entire cache)

**Risk:** If a prompt is updated in S3, the in-memory cache will serve the old version until manually cleared or the process restarts.

**Note:** `.json` enhance profiles are **NOT cached**. Only `.txt` prompts and `.json` prompts (after extracting the `"prompt"` field string) are cached. The full profile dict (with `loras`, `guidance_scale`, etc.) is re-fetched from S3 on every request. \[Confirmed by code: `get_enhance_profile` has no caching, while `get_prompt_from_s3_or_cache` does]

---

### No Other Storage

No DynamoDB, no SQS, no Redis, no local database. The service is stateless except for the in-memory prompt cache.

## 16. Critical Code Deep Dive

### `colour_match` Algorithm (`lab_colour_match.py`)

This is the most algorithmically complex component. Full explanation:

```python
def colour_match(original: np.ndarray, retouched: np.ndarray, preserve_luminance: bool = True) -> np.ndarray:
```

**Input:** Two OpenCV images in BGR format (uint8, 0-255 range)\
**Output:** The `retouched` image with colour statistics matched to `original`, in BGR format

```python
    # Step 1: Convert to LAB colour space (float32 for precision)
    # LAB separates luminance (L) from colour (A=green-red, B=blue-yellow)
    # This allows colour transfer without changing brightness
    orig_lab = cv2.cvtColor(original.astype(np.float32), cv2.COLOR_BGR2LAB)
    ret_lab  = cv2.cvtColor(retouched.astype(np.float32), cv2.COLOR_BGR2LAB)
    
    result = ret_lab.copy()
    
    # Step 2: Determine which channels to process
    # preserve_luminance=True → skip channel 0 (L), only process A and B
    # preserve_luminance=False → process all 3: L, A, B (changes brightness too)
    start_channel = 1 if preserve_luminance else 0
```

**Why LAB?** In RGB, colour and brightness are entangled. If you shift red slightly, you also shift perceived brightness. LAB separates them: L is purely brightness, A and B are purely colour. By working in LAB, we can match only the colour (A+B channels) without touching the brightness (L channel). This is why `preserve_luminance=True` is the default and the recommended setting.

```python
    for ch in range(start_channel, 3):  # ch = 1, 2 (A and B channels)
        
        # Compute statistics of each channel in each image
        orig_mean = orig_lab[:, :, ch].mean()
        orig_std  = orig_lab[:, :, ch].std()
        ret_mean  = ret_lab[:, :, ch].mean()
        ret_std   = ret_lab[:, :, ch].std()
        
        # Guard: if the retouched image has no variance in this channel
        # (e.g., a greyscale image would have std ≈ 0 in A and B)
        # then skip to avoid division by zero
        if ret_std < 1e-6:
            continue
        
        # Reinhard transfer formula:
        # 1. Normalize: subtract retouched mean, divide by retouched std
        #    → centres the channel around 0 with std = 1
        # 2. Scale: multiply by original std
        #    → gives it the same spread as original
        # 3. Shift: add original mean
        #    → centres it around the original mean
        result[:, :, ch] = (ret_lab[:, :, ch] - ret_mean) * (orig_std / ret_std) + orig_mean
```

**Why this formula?** Think of it like standardizing test scores. If school A has scores with mean 70 and std 10, and school B has scores with mean 80 and std 5:

- To make school B's distribution look like school A's: `(B_score - 80) * (10/5) + 70`

- This preserves relative ranking within school B but matches the absolute scale of school A

Applied to colour: it preserves the colour relationships within the enhanced image (relative contrasts) while making the overall colour statistics match the original.

```python
    # Clip to valid LAB range and convert back to BGR
    result = np.clip(result, 0, 255)
    result = cv2.cvtColor(result, cv2.COLOR_LAB2BGR)
    
    return np.clip(result, 0, 255).astype(np.uint8)
```

### `process_image_with_fal` (in `app.py`)

```python
async def process_image_with_fal(prompt, image_url, request, model_name) -> bytes:
    
    # Build base arguments common to all models
    arguments = {
        "prompt": prompt,
        "guidance_scale": request.guidance_scale,
        "num_images": 1,           # Forced to 1 regardless of request.num_images
        "output_format": "jpeg",
        "sync_mode": False,        # Async submission on fal.ai's side
    }
    
    # Model-specific image parameter name
    if model_name in (FAL_MODEL_GEMINE_FLASH, FAL_MODEL_NANO_BANANA, FAL_MODEL_FLUX_2):
        arguments["image_urls"] = [image_url]   # These models take a list
    else:
        arguments["image_url"] = image_url      # FLUX kontext models take a single URL
    
    # FLUX-2 requires explicit image dimensions
    if model_name == FAL_MODEL_FLUX_2:
        arguments["image_size"] = {
            "width": FLUX_2_DEFAULT_WIDTH,   # 884 — hardcoded
            "height": FLUX_2_DEFAULT_HEIGHT  # 1128 — hardcoded
        }
    
    # Optional parameters (only added if set)
    if request.safety_tolerance:
        arguments["safety_tolerance"] = request.safety_tolerance
    
    if request.aspect_ratio:
        arguments["aspect_ratio"] = request.aspect_ratio
    
    # Submit to fal.ai asynchronously
    handler = await fal_client.submit_async(model_name, arguments=arguments)
    
    # Wait for result (this blocks the async task until fal.ai completes)
    result = await handler.get()
    
    # Extract image URL from result
    images = result.get("images", [])
    if not images:
        raise HTTPException(500, "No images returned from FAL model")
    
    image_url_result = images[0].get("url")
    if not image_url_result:
        raise HTTPException(500, "No URL in first image from FAL model result")
    
    # Download the generated image
    return decode_image_from_url_or_data_uri(image_url_result)
```

**Watch out for:** `sync_mode=False` means fal.ai processes asynchronously — but `handler.get()` is a polling/waiting call. The actual HTTP request to this service still waits for fal.ai to finish. Large images or complex prompts can hold the connection open for 30+ seconds.

```python
def get_prompt_from_s3_or_cache(bucket_name: str, prompt_path: str) -> str:
    cache_key = f"{bucket_name}/{prompt_path}"
    
    # ── CACHE HIT ──────────────────────────────────────────────────────
    if cache_key in prompt_cache:
        return prompt_cache[cache_key]
    
    # ── CACHE MISS ─────────────────────────────────────────────────────
    try:
        s3_key = prompt_path.lstrip("/")          # Remove leading slash if present
        response = s3_client.get_object(Bucket=bucket_name, Key=s3_key)
        content = response["Body"].read().decode("utf-8")
        
        # If it's a JSON file, extract just the "prompt" field
        if prompt_path.endswith(".json"):
            data = json.loads(content)
            if isinstance(data, dict) and "prompt" in data:
                content = data["prompt"]
        
        prompt_cache[cache_key] = content
        return content
        
    except Exception as e:
        raise HTTPException(400, f"Failed to retrieve prompt: {str(e)}")
```

**Note on JSON handling in this function:** This function handles `.json` files by extracting just the `"prompt"` string. But for the main enhancement pipeline, when `request.prompt.endswith(".json")`, the code calls `get_enhance_profile()` instead (which returns the full dict). The `get_prompt_from_s3_or_cache` function's JSON handling is a fallback path that is reached only if `.json` is stored as the prompt path in a non-LoRA endpoint. \[Confirmed by code flow in `process_image_enhancement`]

## 19. Junior Developer Summary

### What does this service do in plain English?

Think of it as the **photo editing department**. After the AI-Tagging service has identified all the garment's attributes and the Prompt-Gen service has written the editing instructions, this service does the actual image editing.

Here's what happens when you call it:

1. It takes your garment image and removes the background (sending it to a background-removal tool)

2. It reads the "editing instructions" (the prompt) from a file stored in S3

3. It sends the image + instructions to a powerful AI model on fal.ai to generate an enhanced version

4. Optionally, it corrects the colours to match the original (in case the AI changed them)

5. It resizes the image to the right dimensions

6. It saves the final image to S3

7. It returns the URL where you can find the finished image

### Key things to know as a junior developer

- The service **requires&#x20;****`FAL_KEY`****&#x20;in&#x20;****`.env`** to start. Without it, it crashes immediately on startup.

- There are **6 different AI models** to choose from. Each is a different "photo editor" with different strengths and slightly different API shapes. Use `flux-kontext-pro` as the default.

- The **background removal service** must be running at `http://77.68.113.204:4000` for 5 of the 6 endpoints to work. If you don't have access to that service, disable background removal in the code (set `IS_BACKGROUND_REMOVAL = False`).

- The `prompt` field in the request is not the actual text — it's the S3 path to a file containing the prompt. That file can be a `.txt` (raw text) or `.json` (full enhance profile with LoRA configuration).

- **There is currently a bug (SyntaxError) in the code that prevents the service from starting.** Look for the `enhance_image_by_gemine_nano_banana` function and fix the comment inside the f-string.

- Start the service with: `uvicorn app:app --port 9090` from the `AI-Image-Enhancer/` directory.

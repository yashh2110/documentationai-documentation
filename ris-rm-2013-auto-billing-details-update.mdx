## Overview

The **RIS-RM-2013 – Auto Billing Details Update** macro updates billing address details dynamically based on the order’s SubSource.

It uses predefined mappings to assign correct billing information, ensuring consistency across orders from different sales channels.

<Callout kind="tip" collapsed="false">
  Ensure all comma-separated parameter values are properly aligned to avoid incorrect billing updates.
</Callout>

## Purpose

This macro:

- Identifies order SubSource  
- Matches it with predefined configurations  
- Applies mapped billing details  
- Updates billing information automatically  

👉 In short:  
Update billing address based on order source using predefined mappings.

## When It Runs

Used for billing data automation and validation

Typically runs:

- Manually triggered (per order)  
- During order processing  
- During order validation workflows

## How It Works

<Steps>
  <Step title="Prepare Data" icon="settings" title-type="p">
    Split all comma-separated parameters into structured lists.
  </Step>

  <Step title="Fetch Order" icon="download" title-type="p">
    Retrieve the order using the provided OrderId.
  </Step>

  <Step title="Identify SubSource" icon="search" title-type="p">
    Determine the SubSource of the order.
  </Step>

  <Step title="Match Configuration" icon="link" title-type="p">
    Find the matching index from the SubSource list.
  </Step>

  <Step title="Build Billing Address" icon="edit" title-type="p">
    Construct billing details using matched values:
    - Ignore fields marked as "NA"  
    - Retain existing Full Name and Phone Number  
  </Step>

  <Step title="Update Order" icon="save" title-type="p">
    Apply updated billing address using the API.
  </Step>

  <Step title="Log Results" icon="file-text" title-type="p">
    Record execution details including success and errors.
  </Step>
</Steps>

<Callout kind="warning" collapsed="false">
  - SubSource values must match exactly  
  - All parameter lists must be aligned correctly  
  - Values marked as "NA" are ignored

  - Incorrect mapping may result in wrong billing details  
</Callout>

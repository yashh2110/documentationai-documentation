## 1. Overview

This system helps a business manage daily work in one place.

It supports four main areas:

- Signing in securely

- Viewing business performance on the dashboard

- Importing courier and delivery files

- Creating and managing purchase orders automatically

The most important area in this document is **Purchase Orders** because this is where the system helps keep stock available and reduces manual work.

## 4. Authentication

Authentication means confirming that the right person is entering the system.

### 4.1 Admin Sign In

#### Purpose

Used when an administrator wants to enter the system with login details.

#### What it does

- Checks the admin username and password

- Confirms whether the details are correct

- Grants access to system features after successful sign in

#### When it is used

- At the beginning of the working day

- When an admin needs to manage business settings

- When access to reports or operational tools is required

#### Expected result

- If details are correct, access is allowed

- If details are wrong, access is denied

---

### 4.2 User Sign In by Token

#### Purpose

Used when a normal user signs in with a secure token instead of typing full login details again.

#### What it does

- Accepts a secure token

- Checks whether the token is valid

- Allows access if the token is accepted

#### When it is used

- For faster login

- For users already verified by the business

- In cases where token based access is preferred

#### Expected result

- Valid token gives access

- Invalid token blocks access

## 7. Purchase Order Documentation

## 7.1 Purchase Order Overview

A Purchase Order is a formal buying request sent to a supplier.

It tells the supplier:

- What products are needed

- How many are needed

- What price is expected

- What extra charges may apply

This system supports purchase orders through automation so the business can reorder stock with less manual work.

---

## 7.2 Why Purchase Orders Matter

Purchase orders are important because they help the business:

- Keep enough stock available

- Avoid missing customer sales

- Track what has been ordered from suppliers

- Reduce confusion in purchasing

- Plan costs before stock arrives

Without purchase orders, teams may rely on guesswork, which can lead to stock shortages or overbuying.

---

## 7.3 Purchase Order Automation Overview

Purchase order automation means the system can create purchase related jobs and trigger purchasing actions without someone doing everything manually.

This reduces repetitive work and helps the business respond faster when stock runs low.

---

## 7.4 Create Automation Job

#### Purpose

Creates a purchase order automation rule or job.

#### What it does

- Sets up a repeatable purchasing action

- Allows the system to prepare purchase order activity automatically

- Supports stock based purchasing decisions

#### When it is used

- When the business wants to automate purchasing

- When regular stock checks lead to repeated buying patterns

- When manual purchase creation takes too much time

#### Business value

This is useful for businesses with fast moving products because it helps keep stock levels healthy.

---

## 7.5 Delete Automation Job

#### Purpose

Removes an existing purchase order automation job.

#### What it does

- Stops the selected automation from running

- Prevents future purchase order actions tied to that job

#### When it is used

- When the automation is no longer needed

- When purchasing rules change

- When products are no longer active

#### Business value

This gives the business control and helps avoid unwanted purchase activity.

---

## 7.6 Manual Purchase Order Scheduling

#### Purpose

Allows purchase order activity to be triggered manually.

#### What it does

- Starts purchase order scheduling when a user chooses to run it

- Gives immediate control without waiting for automatic timing

#### When it is used

- In urgent restocking situations

- When the team wants to test the process

- When purchasing needs to happen immediately

#### Business value

This is useful when stock is critically low and the team does not want to wait for the next automatic run.

---

## 7.7 How Purchase Order Automation Works

Below is the simple business flow.

### Step 1. Stock is reviewed

The system looks at stock levels and business conditions.

### Step 2. Rules are checked

The system checks whether a purchase rule applies.

### Step 3. Purchase action is prepared

If the rule matches, the system prepares the purchase order activity.

### Step 4. Manual or automatic run happens

The purchase order process can happen automatically or be triggered manually.

### Step 5. Team reviews the result

The purchasing or operations team can then review the outcome and continue supplier communication if needed.

## 9. Troubleshooting Guide

## 9.1 Cannot Sign In

Check:

- Username and password

- Token validity

- User access rights

---

## 9.2 Dashboard Numbers Look Incorrect

Check:

- Whether the correct user or business view is being used

- Whether recent data has been updated

- Whether date based reports are using the correct time range

---

## 9.3 Courier File Does Not Process Correctly

Check:

- File format

- File contents

- Whether the correct courier file type was selected

---

## 9.4 Purchase Order Automation Is Not Working

Check:

- Whether the automation job exists

- Whether it has been removed by mistake

- Whether stock rules are correctly set

- Whether the process needs to be triggered manually

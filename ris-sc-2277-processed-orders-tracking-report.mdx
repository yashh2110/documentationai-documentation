## Overview

The **Processed Orders Tracking Report** provides a detailed view of all processed orders that have valid tracking numbers.

It combines order, item, customer, shipping, and resend information into a single dataset for complete visibility.

<Callout kind="tip" collapsed="false">
  Only orders with tracking numbers are included to ensure accurate shipment tracking and reporting.
</Callout>

---

## Purpose

This report:

- Retrieves processed orders within a date range  
- Displays SKU-level quantities per order  
- Includes customer, shipping, and location details  
- Identifies resend orders using order relations  

👉 In short:  
Track shipped orders with full details and resend visibility.

---

## How It Works

<Steps>
  <Step title="Filter Processed Orders" icon="filter" title-type="p">
    Selects orders that:
    - Have a processed date  
    - Fall within the given date range  
    - Contain a valid tracking number  
  </Step>

  <Step title="Aggregate Order Items" icon="layers" title-type="p">
    Groups order items by SKU and calculates total quantity per order.
  </Step>

  <Step title="Identify Resend Orders" icon="refresh-ccw" title-type="p">
    Checks <b>Order_Relation</b> table to flag resend orders using:
    - LinkType = "Order Item Resend%"
  </Step>

  <Step title="Join Reference Data" icon="database" title-type="p">
    Enriches data with:
    - SKU details (StockItem)  
    - Country (ListCountries)  
    - Postal service (PostalServices)  
    - Fulfilment location (StockLocation)  
  </Step>

  <Step title="Prepare Output Fields" icon="file-text" title-type="p">
    Formats and derives:
    - Channel Reference (fallback logic)  
    - Order Status (Paid or numeric)  
    - Resend flag (Yes/No)  
  </Step>

  <Step title="Sort Results" icon="arrow-down" title-type="p">
    Orders results by:
    - Processed date (latest first)  
    - Order ID  
    - SKU  
  </Step>
</Steps>

## Important Notes

<Callout kind="warning" collapsed="false">
  - Only orders with tracking numbers are included  

  - SKU is resolved using processed SKU fallback logic  

  - Resend detection depends on Order_Relation data accuracy  

  - Status "1" is mapped to "Paid", others remain numeric  

  - Data uses NOLOCK (may include uncommitted reads)  

  - Quantity is aggregated at SKU level per order  
</Callout>
